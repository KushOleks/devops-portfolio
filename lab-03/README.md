# Лабораторна робота №3 — Власний DevOps-інструментарій

## Завдання 1. Скрипт резервного копіювання

### Призначення

`backup.sh` — Bash-скрипт для автоматичного створення резервних копій директорій.

Скрипт створює стиснені архіви формату `.tar.gz`, додає до назв часові мітки, автоматично видаляє застарілі резервні копії та підтримує режим попереднього перегляду дій.

### Параметри

| Параметр | Призначення |
|---|---|
| `--source PATH` | Шлях до директорії, яку потрібно архівувати. Обов'язковий |
| `--dest PATH` | Директорія для збереження архівів. Обов'язковий |
| `--keep N` | Кількість останніх архівів, які потрібно залишити. Типово 5 |
| `--dry-run` | Показати заплановані дії без створення або видалення файлів |
| `--help` | Вивести довідку |

### Запуск

З кореневої директорії репозиторію:

```bash
chmod +x lab-03/backup.sh
```

Створення резервної копії:

```bash
./lab-03/backup.sh \
  --source /tmp/devops-backup-test/project \
  --dest /tmp/devops-backup-test/backups \
  --keep 3
```

Попередній перегляд:

```bash
./lab-03/backup.sh \
  --source /tmp/devops-backup-test/project \
  --dest /tmp/devops-backup-test/backups \
  --keep 3 \
  --dry-run
```

Виведення довідки:

```bash
./lab-03/backup.sh --help
```

### Пояснення `set -euo pipefail`

На початку скрипта використовується:

```bash
set -euo pipefail
```

- `-e` — зупиняє виконання, якщо команда завершується помилкою, за винятком випадків, де Bash спеціально обробляє її статус. Без цього скрипт міг би продовжити роботу після невдалого створення архіву.
- `-u` — забороняє використання неініціалізованих змінних. Без цього помилка в назві змінної могла б залишитися непоміченою.
- `pipefail` — робить конвеєр команд неуспішним, якщо будь-яка з його команд завершилася помилкою. Без нього Bash зазвичай враховує тільки статус останньої команди конвеєра.

Разом ці налаштування допомагають раніше виявляти помилки та запобігати некоректному виконанню скрипта.

### Коди виходу

| Код | Значення |
|---|---|
| `0` | Успішне виконання |
| `1` | Загальна помилка |
| `2` | Некоректні або відсутні параметри |
| `3` | Джерело не існує або недоступне |
| `4` | Помилка доступу до директорії призначення або створення архіву |

### Журналювання

Скрипт виводить час виконання, джерело, директорію призначення, кількість збережених копій, результат архівування, розмір архіву та кількість видалених копій.

Приклад:

```text
[2026-10-14 10:13:37] Source: /private/tmp/devops-backup-test/project
[2026-10-14 10:13:37] Destination: /private/tmp/devops-backup-test/backups
[2026-10-14 10:13:37] Keep: 3
[2026-10-14 10:13:37] Created: .../project-2026-10-14-101337-72965.tar.gz (522 bytes)
[2026-10-14 10:13:37] Deleted: .../project-2026-10-14-100400-66053.tar.gz
[2026-10-14 10:13:37] Result: archived=1, deleted=1, size=522 bytes
```

Журнал виводиться у стандартний потік виведення, тому за потреби його можна перенаправити у файл.

### Результати тестування

1. **Створення архіву:** створено архів `.tar.gz` розміром 522 байти.
2. **Ротація:** після шести запусків із `--keep 3` залишилися три найновіші архіви.
3. **Dry-run:** скрипт показав заплановане створення та видалення, але кількість і склад файлів не змінилися.
4. **Неіснуюче джерело:** отримано зрозуміле повідомлення про помилку та код виходу `3`.
5. **Шляхи з пробілами:** успішно створено архів `my project-...tar.gz`.
6. **Сторонні файли:** файл `important.txt` і архів іншого джерела не були видалені.
7. **Вміст архіву:** командою `tar -tzf` підтверджено наявність `project/file1.txt` та `project/file2.txt`.

### Обмеження

Скрипт призначений для локального резервного копіювання директорій. Ротація визначає належність архівів за шаблоном імені джерела та часовою міткою. Скрипт не реалізує блокування одночасних запусків, віддалене зберігання або автоматичне відновлення даних. Імена файлів із символами нового рядка не підтримуються повністю під час сортування архівів.

### Висновок

У результаті виконання завдання розроблено Bash-інструмент резервного копіювання з параметрами командного рядка, автоматичною ротацією архівів, режимом `--dry-run`, перевіркою помилок і журналюванням. Основні сценарії роботи перевірено на macOS.
